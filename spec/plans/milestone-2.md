# תוכנית — Milestone 2: הכנת יציאה עם מעט קלט

מבוסס על MILESTONES 1.2, PRD 0.5, ARCHITECTURE 0.3, DESIGN 0.3 והקוד של Milestone 1 (apps/web).

## מטרה בקצרה
להשלים את מסך 03 ״מה בא לכם הפעם?״ ומסך 04 ״הגדרות היציאה״, כך שיציאה (למשל של ארבעה אנשים) מגיעה ל**בקשת חיפוש מובנית** (payload) שניתן לבדוק מקומית — בלי שרת, בלי AI ובלי Google. החיפוש עצמו נבנה ב־Milestone 3; פתרון כתובת ידנית מול שירות חי — ב־Milestone 5.

## מה לא בונים כאן
- אין apps/api ואין packages/contracts (נוצרים ב־Milestone 3). טיפוסי הבקשה נכתבים בינתיים ב־apps/web, וב־Milestone 3 עוברים ל־packages/contracts עם Zod.
- אין קריאה לרשת, אין פתרון כתובת, אין מסך 05.
- אין חניה, אין אלרגיות, אין שמירת היציאה ב־IndexedDB (היציאה בזיכרון בלבד).
- אין כפתור חזרה חדש במסכים 03/04 — חזרה בניווט המערכת, לפי DESIGN 1.4.

## מבנה הנתונים (בזיכרון בלבד)

הרחבת `OutingContext` הקיים. כל הנתונים נשארים בזיכרון עד רענון / סגירת האפליקציה — ללא היסטוריה קבועה.

```ts
// Per-participant food choice for this outing (screen 03)
type FoodMode = 'use_saved' | 'specific' | 'indifferent'
interface OutingFood {
  mode: FoodMode            // default: 'use_saved' (= skip)
  foodTypes: string[]       // used only when mode = 'specific'
  text: string              // used only when mode = 'specific', max 200
}

// Shared settings (screen 04)
interface OutingSettings {
  visitDate: string         // 'YYYY-MM-DD', Israel local date
  visitTime: string         // 'HH:mm', Israel local time
  searchMode: 'travel_time' | 'areas'           // default: 'travel_time'
  originSource: 'current_location' | 'manual_address'  // default: 'manual_address' (no auto permission request)
  currentLocation: { lat: number; lng: number } | null
  manualAddress: string     // max 200
  maxTravelMinutes: 15 | 30 | 45 | 60            // default: 30
  areaIds: string[]
  budgetRanges: BudgetRange[]   // empty = "לא משנה" (default)
  kosher: 'certified' | 'at_least_no_pork_seafood' | 'indifferent'  // default: indifferent
  atmospheres: Atmosphere[]     // empty = "לא משנה" (default), max 2
}
```

- `OutingContext` מחזיק: `selectedIds` (קיים), `foodByPerson: Record<personId, OutingFood>`, `settings: OutingSettings`, ו־`lastRequest` (הבקשה האחרונה שנבנתה + מפת המזהים הזמניים).
- ערכי ״בחירה לערב״ נשמרים גם כשעוברים למצב אחר באותו כרטיס, כך שחזרה ל״בחירה לערב״ מחזירה את מה שהוקלד. בבקשה נכלל רק מה שמתאים למצב הנוכחי.
- משתתף שהוסר מהבחירה — הקלט שלו נשאר בזיכרון אבל אינו נכלל בבקשה. פרופיל שנמחק — הקלט שלו נמחק (הרחבת `prune` הקיים).
- שימור קלט: מעבר 03 → 04 → חזרה ל־03 → חזרה ל־01 → הוספת משתתף → 03: כל הקלט נשאר, ורק כרטיס חדש נוסף.

## צורת בקשת החיפוש (payload)

פונקציה טהורה `buildSearchRequest(...)` ב־`src/domain/searchRequest.ts`, שמחזירה **שני חלקים נפרדים**: הבקשה (מה שיישלח לשרת ב־Milestone 3) ומפת המזהים (נשארת במכשיר).

```ts
interface SearchRequest {
  requestId: string                  // crypto.randomUUID()
  participants: ParticipantRequest[] // in screen-01 order, tokens p1..pn
  sharedFilters: {
    budgetRanges: BudgetRange[] | 'indifferent'
    kosher: Kosher
    atmospheres: Atmosphere[] | 'indifferent'
  }
  visitAt: { local: string; timeZone: 'Asia/Jerusalem'; utc: string }
  searchMode: 'travel_time' | 'areas'
  origin?: { kind: 'current_location'; lat: number; lng: number }
         | { kind: 'manual_address'; text: string }   // travel_time only
  maxTravelMinutes?: 15 | 30 | 45 | 60                 // travel_time only
  areaIds?: string[]                                   // areas only
  excludedRestaurantIds: string[]                      // always [] in M2
}

interface ParticipantRequest {
  token: string                 // 'p1', 'p2', ... — no name, no profile id
  foodMode: FoodMode
  foodTypes: string[]           // effective types after precedence
  outingText?: string           // only in 'specific' and only if non-empty
  profileText?: string          // always sent when the profile has text (low priority)
  diet: Diet                    // always sent
}

type ParticipantMap = Record<string, string>   // token -> personId, device only
```

**כללי קדימות (ARCHITECTURE 2.3):**
| מצב | foodTypes בבקשה | outingText | profileText | diet |
|---|---|---|---|---|
| use_saved (דילוג) | סוגי האוכל מהפרופיל (ריק = ״לא משנה״) | — | תמיד | תמיד |
| specific (בחירה לערב) | הבחירה לערב בלבד (מחליפה את הפרופיל) | אם הוקלד | תמיד | תמיד |
| indifferent (לא משנה) | ריק | — | תמיד | תמיד |

- שדות במסלול: ב־`areas` אין `origin` ואין `maxTravelMinutes`; ב־`travel_time` אין `areaIds`.
- הבקשה **לעולם** אינה כוללת שם, מזהה פרופיל או שדה חניה.
- ההגדרות המשותפות מופיעות פעם אחת ברמת הבקשה, לא אצל כל משתתף.
- אזורים, סוגי אוכל ותקציב נשלחים כמזהי קטלוג (המרה לשמות בעברית — בשרת, ב־Milestone 3–4).

## זמן הביקור (Asia/Jerusalem)

`src/domain/visitTime.ts` — פונקציות טהורות, בלי ספרייה נוספת (Intl המובנה):
- `israelNow(now)` → התאריך והשעה הנוכחיים בשעון ישראל (לא לפי שעון הטלפון).
- `israelLocalToUtc(date, time)` → זמן UTC, כולל שעון קיץ/חורף.
- `isPastVisit(date, time, now)` → האם המועד עבר.
- `defaultVisit(now)` → ברירת מחדל: היום, בשעה העגולה הבאה (למשל 18:20 → 19:00). *(הנחה — ראה ״נקודות לאישור״)*

ממשק: שני רכיבים מובנים של הדפדפן — `type="date"` ו־`type="time"` — זה לצד זה תחת התווית ״תאריך ושעת הביקור״ (כמו ב־Mockup). `min` מוגדר לתאריך של היום בשעון ישראל. כיוון ש־Safari ב־iPhone אינו אוכף `min`, הבדיקה נעשית גם בקוד: מועד שעבר חוסם את הכפתור ומציג הודעה. הבדיקה רצה גם ברגע הלחיצה (למקרה שהזמן עבר בזמן שהמסך פתוח).

## מסך 03 — ״מה בא לכם הפעם?״ (`/outing/preferences`)

החלפת המסך הזמני של Milestone 1.
- כותרת, ההסבר ״אפשר לדלג ולהשתמש בפרופיל השמור״, כרטיס לכל משתתף לפי סדר מסך 01.
- בכל כרטיס: שם (`<bdi>`), שלוש אפשרויות בבחירה יחידה (`SingleChipGroup`): ״לפי הפרופיל״ / ״בחירה לערב״ / ״לא משנה״. ברירת מחדל: ״לפי הפרופיל״.
  - **לפי הפרופיל:** תקציר קריאה בלבד (לא שדה קלט): סוגי האוכל השמורים (או ״לא משנה״), והטקסט החופשי של הפרופיל אם יש.
  - **בחירה לערב:** תגיות סוגי אוכל בבחירה מרובה (בלי תגית ״לא משנה״ — היא מצב נפרד), ושדה טקסט עד 200 תווים עם מונה. אם אין סוג ואין טקסט: ״בחרו לפחות סוג אוכל אחד או כתבו מה מתחשק״ בכרטיס, וכפתור ההמשך אינו פעיל.
  - **לא משנה:** שורת אישור ״אין העדפת סוג אוכל ליציאה הזו״.
  - בכל המצבים, אם בפרופיל יש תזונה: ״תזונה: צמחוני״ / ״תזונה: טבעוני״ — לקריאה בלבד.
- כפתור ״המשך להגדרות המשותפות״ → `/outing/settings`.
- אין משתתפים נבחרים → חזרה למסך 01 (כמו היום).
- ההעדפה לערב אינה נכתבת לפרופיל ולא ל־IndexedDB.

## מסך 04 — ״הגדרות היציאה״ (`/outing/settings`, מסך חדש)

סדר התוכן לפי DESIGN 1.5:
1. **תאריך ושעת הביקור** — ראה למעלה.
2. **איפה מחפשים?** — ״לפי זמן נסיעה״ / ״לפי ערים / אזורים״ (בחירה יחידה).
3. **במסלול זמן נסיעה:**
   - ״נקודת מוצא״: ״המיקום הנוכחי״ / ״כתובת ידנית״ (בחירה יחידה; ברירת מחדל ״כתובת ידנית״, כדי שבקשת הרשאת המיקום תופיע רק אחרי בחירה של המשתמש).
   - ״המיקום הנוכחי״ → בקשת מיקום מהדפדפן. במהלך הבקשה: ״מאתרים את המיקום…״; בהצלחה: ״המיקום התקבל״; בסירוב / כשל / זמן ארוך מדי: ״לא ניתן לקבל את המיקום. אפשר להזין כתובת או לחפש לפי ערים / אזורים.״ — שאר האפשרויות נשארות פעילות.
   - ״כתובת ידנית״ → שדה טקסט עם placeholder ״הזינו כתובת מוצא״ (עד 200 תווים). הכתובת נשמרת כטקסט בלבד; פתרון מול Google ב־Milestone 5.
   - ״זמן נסיעה מרבי״: תגיות 15 / 30 / 45 / 60 דקות, בחירה יחידה, ברירת מחדל 30, בלי ״לא משנה״ (DESIGN גובר על ה־Mockup).
   - בלי נקודת מוצא תקינה (אין מיקום שהתקבל / כתובת ריקה): הכפתור אינו פעיל, ומוצג ״בחרו את המיקום הנוכחי או הזינו כתובת״.
4. **במסלול אזורים:** תגיות עשרת האזורים מהקטלוג (ARCHITECTURE 2.3), בחירה מרובה, בלי ״לא משנה״. בלי אזור: הכפתור אינו פעיל + ״בחרו לפחות אזור אחד״. אין בקשת מיקום. שדות המוצא וזמן הנסיעה מוסתרים (ערכיהם נשמרים בזיכרון אם חוזרים למסלול נסיעה, אבל לא נכללים בבקשה).
5. **תקציב לאדם** — תגיות בחירה מרובה: ״עד 100 ₪״, ״100–200 ₪״, ״200–300 ₪״, ״300–400 ₪״, ״400 ₪ ומעלה״ + ״לא משנה״ (בלעדי, ברירת מחדל).
6. **העדפות נוספות** — אזור מתקפל (כפתור עם `aria-expanded`), מכווץ בהתחלה:
   - **כשרות:** ״כשר עם תעודה״ / ״לפחות ללא חזיר ופירות ים״ / ״לא משנה״ (בחירה יחידה, ברירת מחדל ״לא משנה״; התווית הארוכה נשברת לשורות).
   - **אווירה:** ״רומנטית״, ״משפחתית״, ״תוססת״, ״שקטה״, ״עסקית״ + ״לא משנה״ (בלעדי, ברירת מחדל). כשנבחרו שתיים — שאר התגיות לא פעילות ומוצג ״אפשר לבחור עד שתי אווירות״.
7. **״מצאו לנו מסעדות״** — אם הכל תקין: בונה את הבקשה, שומר אותה ב־`lastRequest` ומציג **תצוגה זמנית** מתחת לכפתור: ״בקשת החיפוש מוכנה. החיפוש עצמו ייבנה באבן הדרך הבאה.״ ואת תוכן הבקשה (JSON) בתיבה נגללת — כדי שתוכל לבדוק בעיניים שאין בה שמות ושאין origin במסלול אזורים. התצוגה הזמנית תוסר ב־Milestone 3. הבקשה אינה נכתבת ל־console או ללוגים.

## בדיקות אוטומטיות (Vitest)

- **קדימות אוכל:** ״בחירה לערב״ מחליפה את סוגי הפרופיל; טקסט הפרופיל ותזונה נשלחים בכל שלושת המצבים; דילוג משתמש בפרופיל; ״לא משנה״ → אין סוגי אוכל; ״לא משנה״ ודילוג מפיקים בקשות שונות; אובייקט הפרופיל לא משתנה.
- **תקינות מסך 03:** ״בחירה לערב״ ריקה לא תקינה; סוג אחד או טקסט בלבד — תקין; טקסט עם רווחים בלבד — לא תקין.
- **הגדרות משותפות:** ״לא משנה״ בלעדי בתקציב ובאווירה; לא ניתן לבחור אווירה שלישית; כמה טווחי תקציב אפשריים; אזורים — לפחות אחד; מוצא — מיקום או כתובת לא ריקה.
- **בקשה:** בארבעה משתתפים יש `sharedFilters` אחד בלבד; טוקנים p1..p4 לפי סדר מסך 01; ה־JSON לא מכיל שמות ולא מזהי פרופיל (בדיקה על המחרוזת המלאה, כולל שם מעורב עברית/אנגלית); במסלול אזורים אין `origin` ו־`maxTravelMinutes`; במסלול נסיעה אין `areaIds`; אין מפתח שמכיל ״parking״; משתתף שהוסר מהבחירה לא נכלל; `excludedRestaurantIds` ריק.
- **זמן:** 29.10.2026 20:00 (שעון חורף) → 18:00Z; תאריך בקיץ → הפרש 3 שעות; התוצאה זהה גם כשאזור הזמן של המחשב שונה (הרצה עם TZ אחר); מועד שעבר מזוהה; ברירת המחדל היא שעה עגולה עתידית.

## סיכונים והערות
- **חזרה אחורה ב־iPhone במצב מותקן:** לפי DESIGN החזרה היא בניווט המערכת. באפליקציה מותקנת ב־iPhone אין כפתור חזרה של הדפדפן; יש לבדוק בטלפון שתנועת ההחלקה מהקצה עובדת. אם לא — לעצור ולשאול לפני שמוסיפים כפתור (שינוי DESIGN).
- **תצוגת התאריך:** הרכיב המובנה מציג את התאריך לפי שפת הטלפון (בטלפון באנגלית עשוי להופיע 10/29/2026). זו התנהגות הרכיב המובנה שנבחר ב־DESIGN.
- **מיקום:** פועל רק ב־localhost או ב־HTTPS (הקישור הזמני). בדפדפן המחשב ייתכן מיקום לא מדויק — לא משנה בשלב זה.
- **רענון הדף** מאפס את היציאה (בזיכרון בלבד, לפי הארכיטקטורה); הפרופילים נשמרים.

## נקודות לאישור (פרטים קטנים שה־spec אינו מגדיר)
1. **ברירת מחדל לתאריך ולשעה:** היום, בשעה העגולה הבאה (אפשר לשנות).
2. **ברירת מחדל לנקודת מוצא:** ״כתובת ידנית״ — כדי שהטלפון לא יבקש הרשאת מיקום לפני שבחרת בה.
3. **נוסחים שאינם מופיעים ב־DESIGN:** ״אין העדפת סוג אוכל ליציאה הזו״, placeholder ״מה מתחשק? תיאור אוכל בלבד״ (בבחירה לערב), ״מאתרים את המיקום…״, ״המיקום התקבל״, ״בחרו את המיקום הנוכחי או הזינו כתובת״, ״בחרו מועד עתידי״, והתצוגה הזמנית ״בקשת החיפוש מוכנה. החיפוש עצמו ייבנה באבן הדרך הבאה.״
4. **תצוגה זמנית של הבקשה** אחרי ״מצאו לנו מסעדות״ — כדי שתוכל לבדוק בעצמך; תוסר ב־Milestone 3.
