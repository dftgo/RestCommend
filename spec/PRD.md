# PRD — אפליקציה לבחירת מסעדה לקבוצה

גרסה: 0.3 · תאריך: 23.10.2026 · סטטוס: טיוטה לאישור

## 1. רקע ומטרות

### מטרת המוצר
לעזור לחברים ולמשפחה לבחור מסעדה בישראל שמתאימה למשתתפים יחד, תוך צמצום ההזנה החוזרת וההתלבטות הקבוצתית.

### הבעיה
לכל סועד טעמים והעדפות תזונתיות משלו. בנוסף, מה שמתחשק לאדם בערב מסוים עשוי להיות שונה מהעדפותיו הרגילות. חיפוש ידני מחייב לשלב את כל אלה עם תקציב, מיקום ואווירה.

### הפתרון
אפליקציית Mobile native ל־iOS ול־Android, בעברית וב־RTL, ללא הרשמה. אדם אחד מנהל במכשיר שלו פרופילים מקומיים, בוחר את משתתפי היציאה, מציין העדפות לערב והגדרות משותפות ומקבל רשימה מדורגת של חמש מסעדות. מנוע OpenAI מחפש מידע ברשת ומנמק את ההתאמה לכל משתתף ולקבוצה.

עקרונות המוצר:
- העדפה לערב מקבלת קדימות על העדפה כללית באותו נושא.
- הגדרות היציאה מוזנות פעם אחת עבור הקבוצה.
- לכל פרמטר סינון קיימת אפשרות ״לא משנה״ שמסירה אותו מהסינון.
- חיפוש לפי זמן נסיעה וחיפוש לפי ערים / אזורים הם שני מסלולים חלופיים.
- התאמה לדרישות הקבוצה קודמת לדירוגים ברשת. רק כשאין חמש התאמות מלאות מוסיפים התאמות חלקיות, לפי מספר פרמטרים חריגים עולה.

## 2. קהלי יעד וצרכי משתמשים

### User Personas
**מארגן יציאה עם חברים:** מזין עבור כולם במכשיר אחד ורוצה להגיע לבחירה משותפת עם מעט שאלות.

**מארגן יציאה משפחתית:** חוזר לאכול עם אנשים מוכרים ורוצה להשתמש בהעדפות שנשמרו, עם אפשרות לעדכן את החשק לערב.

אלה תרחישי שימוש של אותו קהל כללי; אין תפקידים והרשאות שונים.

### User Stories
- כמשתמש, אני רוצה לשמור פרופיל של כל סועד כדי שלא אצטרך להזין מחדש את העדפותיו.
- כמשתמש, אני רוצה לבחור מי מצטרף הפעם כדי שרק המשתתפים שנבחרו ישפיעו על ההמלצות.
- כמשתמש, אני רוצה להזין לכל משתתף מה מתחשק לו הערב, בלי לשנות את הפרופיל הקבוע.
- כמשתמש, אני רוצה לחפש לפי זמן נסיעה מנקודת מוצא או לפי ערים / אזורים ללא מגבלת זמן נסיעה.
- כמשתמש, אני רוצה להבין מדוע כל מסעדה מתאימה לכל סועד ולקבוצה, ובמה היא מתאימה רק באופן חלקי.
- כמשתמש, אני רוצה לשתף את ההמלצות, לשמור מסעדות במועדפים ולבקש עוד חמש אפשרויות.

## 3. זרימות וחוויית משתמש

### User Journey
1. בשימוש הראשון מוסיפים את האנשים הרלוונטיים ואת העדפותיהם הקבועות. בשימוש חוזר בוחרים מתוך הפרופילים השמורים.
2. בוחרים משתתפים ליציאה הנוכחית.
3. לכל משתתף אפשר לענות על שאלה אחת: ״מה בא לך לאכול ביציאה הזו?״. ניתן לדלג ולהשתמש בהעדפות השמורות.
4. בוחרים תאריך ושעה ליציאה, מסלול חיפוש, מיקום ותקציב עבור כולם. התאריך והשעה מוזנים פעם אחת לקבוצה, לרבות מועד עתידי.
5. לפי הצורך פותחים ״העדפות נוספות״ עבור כשרות, חניה ואווירה.
6. מפעילים את החיפוש ורואים ״מחפשים מסעדות שיתאימו לכולם…״ בזמן העבודה.
7. מקבלים חמש המלצות מדורגות עם נימוקים, כתובת, טווח מחיר משוער לאדם, מידע על חניה וקישור. בחיפוש לפי זמן נסיעה מוצג גם זמן נסיעה משוער.
8. משתפים את המסעדות וההסבר הקבוצתי בלבד, שומרים מסעדה במועדפים או מבקשים המלצות נוספות. שמות והסברים אישיים אינם נכללים בשיתוף.

### User Flows
**ניהול פרופילים:** פרופילים ← הוספה או עדכון פרופיל ← שמירה במכשיר.

**חיפוש לפי זמן נסיעה:** בחירת משתתפים ← העדפות לערב ← בחירת מיקום נוכחי או כתובת ידנית ← זמן נסיעה מרבי ← הגדרות משותפות ← חיפוש ← המלצות.

**חיפוש לפי אזורים:** בחירת משתתפים ← העדפות לערב ← בחירת ערים / אזורים בישראל ← הגדרות משותפות ← חיפוש ← המלצות. במסלול זה לא נדרשים נקודת מוצא או זמן נסיעה, ואין סינון לפיהם.

**המלצות נוספות:** תוצאות ← ״המלצות נוספות״ ← חיפוש באותם פרמטרים, תוך החרגת מסעדות שכבר הוצגו בחיפוש הנוכחי ← עד חמש מסעדות חדשות.

**כישלון חיפוש:** הודעת שגיאה ← ״ניסיון חוזר״ ← חזרה על הבקשה תוך שימור הקלט.

### UX Requirements
- אין שאלון מלא שחוזר עבור כל סועד; ההגדרות המשותפות מופיעות פעם אחת בלבד.
- בפרופיל נשמרות העדפות כלליות ותזונה. ההעדפה לערב נשארת נפרדת מהן.
- סוג האוכל הרצוי ליציאה הוא השדה האישי המרכזי: בחירה של סוג אחד או כמה מתוך רשימה, ובנוסף אפשרות לטקסט חופשי. סוג האוכל / המסעדה נכלל בו ללא שאלה אישית כפולה על אותו נושא.
- ״לא משנה״ בפרמטר משותף מסיר אותו מהסינון. דילוג על העדפת אוכל לערב משתמש בפרופיל השמור, כפי שסוכם; אפשרות זו תנוסח בנפרד כדי לא לבלבל עם ״לא משנה״.
- ״לא משנה״ בהעדפת אוכל לערב משמעו שאין העדפה קולינרית באותו נושא בחיפוש הזה; אין בכך מחיקה של הפרופיל.
- אין בחירה של ״חובה״ לעומת ״העדפה״ ואין הגדרת משקלים על ידי המשתמש.
- ממשק עברי ב־RTL אמיתי, לרבות סדר רכיבים, יישור וניווט. אין להפוך תווי עברית ידנית.
- הכיוון הוויזואלי מבוסס על Inspiration Board שאושר: שמנת, פחם, בורדו, זהב עמום וירוק זית, עם אווירה חמה ואלגנטית וצילום אוכל. לוגו המלון שמופיע ברפרנס הוא מקור השראה בלבד ואינו מיתוג האפליקציה.

## 4. דרישות פונקציונליות

### Features & Functional Requirements

| מזהה | דרישה | קריטריון קבלה |
|---|---|---|
| FR-01 | שימוש ללא הרשמה | ניתן ליצור פרופילים ולהפעיל חיפוש ללא חשבון או התחברות. |
| FR-02 | פרופילי סועדים מקומיים | שם לתצוגה, העדפות אוכל כלליות ותזונה זמינים אחרי סגירה ופתיחה מחדש. |
| FR-03 | בחירת משתתפים | החיפוש כולל רק את הפרופילים שנבחרו ליציאה. |
| FR-04 | העדפה לערב | העדפה זמנית גוברת על ההעדפה הכללית באותו נושא בלי לשנות את הפרופיל. |
| FR-05 | חיפוש לפי זמן נסיעה | ניתן לבחור מיקום נוכחי או כתובת ידנית ולהגדיר זמן נסיעה מרבי. |
| FR-06 | חיפוש לפי ערים / אזורים | ניתן לבחור ערים / אזורים בישראל ללא תלות בזמן נסיעה וללא דרישת מיקום המכשיר. |
| FR-07 | תקציב משותף לאדם | מוצגים טווחים במדרגות של 100 ₪: 0–100, 100–200 וכן הלאה, וכן ״לא משנה״. בקצוות משותפים לא תהיה כפילות לוגית בין טווחים. |
| FR-08 | העדפות נוספות משותפות | כשרות: ״כשר עם תעודה״, ״ללא תעודה אך ללא חזיר ופירות ים״, ״לא משנה״. חניה: נמוכה / בינונית / גבוהה / לא משנה. אווירה: בחירה או ״לא משנה״. |
| FR-09 | יצירת המלצות עם חיפוש ברשת | הבקשה עוברת דרך Backend ל־OpenAI, עם הפרמטרים הפעילים והעדפות המשתתפים ללא שמותיהם. |
| FR-10 | תוצאות מדורגות | יעד של חמש מסעדות אמיתיות, עם מיקום בדירוג, הסבר לכל משתתף ולקבוצה, כתובת, טווח מחיר משוער לאדם, מידע על חניה וקישור. במסלול זמן נסיעה מוצג גם זמן נסיעה משוער. |
| FR-11 | התאמות חלקיות | רק כשאין חמש התאמות מלאות משלימים בהתאמות חלקיות; חריגה מפרמטר אחד קודמת לחריגה משניים, וכן הלאה. מותר לחרוג גם מתקציב, אזור או זמן נסיעה, תוך פירוט החריגות. היקף ישראל נשמר. |
| FR-12 | המלצות נוספות | הבקשה מחזירה עוד חמש מסעדות לפי אותם פרמטרים, ללא חזרה על מסעדות שכבר הוצגו באותו חיפוש, ככל שקיימות תוצאות נוספות. |
| FR-13 | מועדפים | ניתן לשמור מסעדה במכשיר ולחזור אליה בשימוש עתידי. |
| FR-14 | שיתוף רשימה | ניתן לשתף מסעדות, קישורים והסבר קבוצתי באמצעות אפשרויות השיתוף של המכשיר. אין לכלול שמות משתתפים, מזהים או הסברים אישיים בשיתוף. |
| FR-15 | טעינה וכישלון | בזמן העבודה מופיע מצב טעינה ברור; בכישלון מופיעה הודעת שגיאה וכפתור ״ניסיון חוזר״. |

| FR-16 | מועד היציאה | ניתן לבחור תאריך ושעה, לרבות מועד עתידי; החיפוש מתחשב בשעות הפתיחה למועד שנבחר ומסמן מידע לא מאומת. |
| FR-17 | דירוגים וביקורות ברשת | החיפוש אוסף דירוגים וביקורות מאתרים רלוונטיים ומשתמש בהם לאחר התאמה לדרישות הקבוצה. המקורות שעליהם מסתמכים נשמרים עם התוצאה לצורך ביסוס ההסבר. |

### כללי התאמה
1. עבור כל משתתף מורכבת תמונת העדפות מהפרופיל ומהעדפת הערב, בהתאם לכללי הקדימות.
2. פרמטרים שסומנו ״לא משנה״ אינם משפיעים על הסינון או הדירוג.
3. סדר הקדימות: התאמות מלאות לפני התאמות חלקיות; בין התאמות חלקיות מספר קטן יותר של פרמטרים חריגים מקבל קדימות. בין מסעדות בעלות התאמה דומה לדרישות המשתתפים והקבוצה, דירוגים וביקורות ברשת משמשים להעדפה. דירוג גבוה ברשת אינו עוקף את סדר ההתאמה הזה.
4. רק כאשר אין חמש התאמות מלאות משלימים את הרשימה בהתאמות חלקיות. כל חריגה מפורטת במפורש. כלל זה חל גם על בקשת המלצות נוספות, לאחר הסרת מסעדות שכבר הוצגו.
5. דירוגים ממקורות שונים אינם מוצגים כאילו נמדדו באותה סקאלה; מידע חסר אינו הופך לדירוג מומצא. שיטת שקלול מספר הביקורות, עדכניותן והמקורות תוגדר ב־Architecture תוך שמירה על קדימות דרישות הקבוצה.
6. התאריך והשעה משמשים לבדיקת שעות פתיחה לפי המידע הזמין, ואינם הבטחה לשולחן פנוי.
7. אין להמציא מסעדות, קישורים או נתוני חניה / נסיעה כדי להשלים חמש תוצאות. מידע חסר או משוער יסומן בהתאם.

### Edge Cases & Error Handling
- **אין משתתפים שנבחרו:** יש להשלים בחירה לפני שליחת הבקשה.
- **אין העדפה לערב:** משתמשים בהעדפות הקבועות, אם קיימות.
- **העדפות סותרות בקבוצה:** מוצגות האפשרויות המתאימות ביותר עם הסבר על ההתאמה והפערים לכל משתתף.
- **פחות מחמש תוצאות מבוססות:** מוצגות התוצאות הזמינות והסבר שלא נמצאו חמש; אין השלמה מלאכותית.
- **אין מסעדות חדשות:** מוסבר שלא נמצאו המלצות נוספות בפרמטרים הנוכחיים.
- **אין הרשאת מיקום:** ניתן להזין כתובת ידנית או לבחור בחיפוש לפי ערים / אזורים.
- **אין חיבור או כשל בשירות:** הודעת שגיאה וניסיון חוזר, בלי לאבד את פרטי היציאה. חיפוש המלצות חדשות מחייב חיבור לרשת.
- **מידע ברשת חסר או לא חד־משמעי:** מוצגת אי־הוודאות במקום לייחס למסעדה נתון ודאי, לרבות כשרות, חניה, מחירים, שעות פתיחה ודירוגים.
- **מועד עתידי:** תוצאת החיפוש מבוססת על שעות הפתיחה הידועות, עם סימון אי־ודאות כשאין מידע למועד שנבחר.
- **שיתוף:** ההסברים האישיים נשארים בתצוגת המכשיר ואינם נכללים בטקסט המשותף.

## 5. דרישות טכניות ואילוצים

| תחום | החלטה מאושרת |
|---|---|
| Platforms | אפליקציית Mobile native ל־iOS ול־Android. בחירת הטכנולוגיה בשלב Architecture. |
| שפה וכיווניות | עברית, RTL. |
| היקף גאוגרפי | ישראל בלבד בגרסה הראשונה. |
| Authentication | ללא הרשמה וללא התחברות. |
| שמירה | פרופילי סועדים ומועדפים נשמרים במכשיר בלבד; אין סנכרון בין מכשירים. |
| אופן שימוש קבוצתי | אדם אחד מזין עבור כל המשתתפים במכשיר שלו. |
| AI | OpenAI עם חיפוש ברשת לצורך הפקת המלצות. בחירת מודל ודרך החיפוש בשלב Architecture. |
| Backend | הגישה ל־AI דרך Backend בלבד; מפתחות API אינם נחשפים באפליקציה. |
| פרטיות הבקשה | שמות המשתתפים אינם נשלחים ל־AI. מזהים זמניים מקשרים את ההסברים בחזרה לשמות במכשיר. |
| העברת נתונים | לצורך החיפוש מועברות העדפות ומועברים פרטי המיקום הדרושים. שמירה מקומית אינה משמעה שכל העיבוד מתרחש במכשיר. |
| מיקום וזמן נסיעה | תמיכה במיקום נוכחי או כתובת ידנית במסלול זמן נסיעה. מקור ואופן חישוב זמן הנסיעה ייקבעו ב־Architecture. |
| תלות ברשת | חיפוש ברשת ויצירת המלצות מחייבים חיבור. |
| תהליך עבודה | Gated: אישור PRD לפני Architecture, ובהמשך אישור כל שלב. |

מדיניות שמירה של בקשות אצל שירותי העיבוד, מנגנוני הגנה על ה־Backend ומקורות נתוני חניה / נסיעה יפורטו בשלב Architecture. אין בשלב זה התחייבות למדיניות של ספק חיצוני או לנתוני זמן אמת.

## 6. Out of Scope

- איסוף אלרגיות ורגישויות, שמירתן, סינון לפיהן או העברתן ל־AI. לא יופיעו שדות או הסברים בנושא בממשק.
- הרשמה, התחברות, חשבונות ותפקידים שונים.
- שמירת פרופילים או מועדפים בשרת וסנכרונם בין מכשירים.
- מילוי ההעדפות על ידי משתתפים ממכשירים נפרדים.
- המלצות מחוץ לישראל.
- סינון לפי נגישות או התאמה לילדים.
- שדות נפרדים נוספים כגון רמת רעש וישיבה בפנים / בחוץ בגרסה הראשונה; אווירה נשארת פרמטר משותף אחד.
- הזמנת שולחן, תשלום, משלוחים או הבטחת זמינות שולחנות וחניה בזמן אמת.
- בחירת דרישות ״חובה״ / ״העדפה״ או משקלים ידניים.
- שמירת היסטוריית חיפושים לא הוגדרה כחלק מגרסה זו.
- תחילת פיתוח אינה חלק משלב התכנון הנוכחי.
