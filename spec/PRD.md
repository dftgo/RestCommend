# PRD — אפליקציה לבחירת מסעדה לקבוצה

גרסה: 0.5 · תאריך: 24.10.2026 · סטטוס: מאושר

## 1. רקע ומטרות

### מטרת המוצר
לעזור לחברים ולמשפחה לבחור מסעדה בישראל שמתאימה למשתתפים יחד, תוך צמצום ההזנה החוזרת וההתלבטות הקבוצתית.

### הבעיה
לכל סועד טעמים והעדפות תזונתיות משלו. בנוסף, מה שמתחשק לאדם בערב מסוים עשוי להיות שונה מהעדפותיו הרגילות. חיפוש ידני מחייב לשלב את כל אלה עם תקציב, מיקום ואווירה.

### הפתרון
אפליקציית אינטרנט לטלפון (Progressive Web App) שנשמרת למסך הבית ב־iPhone וב־Android ונפתחת כמו אפליקציה, בעברית וב־RTL, ללא הרשמה וללא עלות התקנה, לשימוש פרטי של משפחה וחברים קרובים. האפליקציה מופצת באמצעות קישור ואינה מתפרסמת בחנויות האפליקציות. אדם אחד מנהל במכשיר שלו פרופילים מקומיים, בוחר את משתתפי היציאה, מציין העדפות לערב והגדרות משותפות ומקבל רשימה מדורגת של חמש מסעדות. מנוע OpenAI מחפש מידע ברשת ומנמק את ההתאמה לכל משתתף ולקבוצה.

עקרונות המוצר:
- העדפה לערב מקבלת קדימות על העדפה כללית ועל הטקסט החופשי שבפרופיל.
- הגדרות היציאה מוזנות פעם אחת עבור הקבוצה.
- לכל פרמטר סינון משותף קיימת אפשרות ״לא משנה״ שמסירה אותו מהסינון. החריגים הם בחירת האזורים במסלול אזורים ובחירת זמן הנסיעה במסלול זמן נסיעה, שהם עצם המסלול שנבחר.
- חיפוש לפי זמן נסיעה וחיפוש לפי ערים / אזורים הם שני מסלולים חלופיים.
- התאמה לדרישות הקבוצה קודמת לדירוגים ברשת. רק כשאין חמש מסעדות ללא חריגה ידועה מוסיפים התאמות חלקיות, לפי מספר פרמטרים חריגים עולה.

### יעדים ומדדי הצלחה
- **מהירות:** ברוב החיפושים התוצאות מוצגות תוך 30 שניות מלחיצה על ״מצאו לנו מסעדות״.
- **איכות:** ברוב החיפושים מוצגות לפחות שלוש מסעדות ללא חריגה ידועה מהדרישות שנבחרו.
- **אמינות:** אף תוצאה אינה מכילה מסעדה, קישור, מחיר או דירוג שהומצאו; כל קישור נפתח לעמוד של המסעדה שהוצגה.
- **קלות שימוש:** הכנת יציאה של ארבעה אנשים עם פרופילים שמורים אורכת פחות מדקה.

המדדים נבדקים על מדגם יציאות במהלך הפיתוח; אינם הבטחה לכל חיפוש.

## 2. קהלי יעד וצרכי משתמשים

### User Personas
**מארגן יציאה עם חברים:** מזין עבור כולם במכשיר אחד ורוצה להגיע לבחירה משותפת עם מעט שאלות.

**מארגן יציאה משפחתית:** חוזר לאכול עם אנשים מוכרים ורוצה להשתמש בהעדפות שנשמרו, עם אפשרות לעדכן את החשק לערב.

אלה תרחישי שימוש של אותו קהל כללי — משפחה וחברים קרובים; אין תפקידים והרשאות שונים.

### User Stories
- כמשתמש, אני רוצה לשמור פרופיל של כל סועד כדי שלא אצטרך להזין מחדש את העדפותיו.
- כמשתמש, אני רוצה למחוק פרופיל של אדם שאינו רלוונטי עוד, ולהסיר מסעדה מהמועדפים.
- כמשתמש, אני רוצה לבחור מי מצטרף הפעם כדי שרק המשתתפים שנבחרו ישפיעו על ההמלצות.
- כמשתמש, אני רוצה להזין לכל משתתף מה מתחשק לו הערב, בלי לשנות את הפרופיל הקבוע.
- כמשתמש, אני רוצה לחפש לפי זמן נסיעה מנקודת מוצא או לפי ערים / אזורים ללא מגבלת זמן נסיעה.
- כמשתמש, אני רוצה להבין מדוע כל מסעדה מתאימה לכל סועד ולקבוצה, ובמה היא מתאימה רק באופן חלקי או שלא נמצא עליה מידע.
- כמשתמש, אני רוצה לשתף את ההמלצות, לשמור מסעדות במועדפים ולבקש עוד חמש אפשרויות.

## 3. זרימות וחוויית משתמש

### User Journey
1. בשימוש הראשון מוסיפים את האנשים הרלוונטיים ואת העדפותיהם הקבועות. בשימוש חוזר בוחרים מתוך הפרופילים השמורים.
2. בוחרים משתתפים ליציאה הנוכחית (עד 10).
3. לכל משתתף אפשר לענות על שאלה אחת: ״מה בא לך לאכול ביציאה הזו?״. ניתן לדלג ולהשתמש בהעדפות השמורות.
4. בוחרים תאריך ושעה ליציאה, מסלול חיפוש, מיקום ותקציב עבור כולם. התאריך והשעה מוזנים פעם אחת לקבוצה, לרבות מועד עתידי.
5. לפי הצורך פותחים ״העדפות נוספות״ עבור כשרות ואווירה.
6. מפעילים את החיפוש ורואים ״מחפשים מסעדות שיתאימו לכולם…״ בזמן העבודה.
7. מקבלים חמש המלצות מדורגות עם נימוקים, כתובת, טווח מחיר משוער לאדם וקישור לאתר המסעדה — או, כשאין לה אתר, לעמוד אחר שמתאר אותה. בחיפוש לפי זמן נסיעה מוצג גם זמן נסיעה משוער.
8. משתפים את המסעדות וההסבר הקבוצתי בלבד, שומרים מסעדה במועדפים או מבקשים המלצות נוספות, שמתווספות מתחת לקודמות. שמות והסברים אישיים אינם נכללים בשיתוף.

### User Flows
**ניהול פרופילים:** פרופילים ← הוספה, עדכון או מחיקה (באישור) של פרופיל ← שמירה במכשיר.

**חיפוש לפי זמן נסיעה:** בחירת משתתפים ← העדפות לערב ← בחירת מיקום נוכחי או כתובת ידנית ← זמן נסיעה מרבי (15 / 30 / 45 / 60 דקות) ← הגדרות משותפות ← חיפוש ← המלצות.

**חיפוש לפי אזורים:** בחירת משתתפים ← העדפות לערב ← בחירת אזור אחד או יותר מתוך רשימה קבועה בישראל ← הגדרות משותפות ← חיפוש ← המלצות. במסלול זה לא נדרשים נקודת מוצא או זמן נסיעה, ואין סינון לפיהם.

**המלצות נוספות:** תוצאות ← ״המלצות נוספות״ ← חיפוש באותם פרמטרים, תוך החרגת מסעדות שכבר הוצגו בחיפוש הנוכחי ← עד חמש מסעדות חדשות שמתווספות מתחת לתוצאות הקודמות.

**מועדפים:** לב בכרטיס מסעדה ← שמירה במועדפים; לחיצה על לב מלא ← הסרה מהמועדפים.

**כישלון חיפוש:** הודעת שגיאה ← ״ניסיון חוזר״ ← חזרה על הבקשה תוך שימור הקלט.

### UX Requirements
- אין שאלון מלא שחוזר עבור כל סועד; ההגדרות המשותפות מופיעות פעם אחת בלבד.
- בפרופיל נשמרים סוגי אוכל אהובים, טקסט חופשי ״משהו נוסף שאוהבים?״ והעדפת תזונה. ההעדפה לערב נשארת נפרדת מהם.
- פרופיל שלא נבחר בו אף סוג אוכל נחשב ״לא משנה״ לגבי סוג האוכל.
- סוג האוכל הרצוי ליציאה הוא השדה האישי המרכזי: בחירה של סוג אחד או כמה מתוך רשימה, ובנוסף אפשרות לטקסט חופשי. ב״בחירה לערב״ יש לבחור לפחות סוג אחד או לכתוב טקסט; אחרת לא ניתן להמשיך.
- הטקסט החופשי מהפרופיל נשמר תמיד ומועבר לחיפוש, גם כשנבחרה ״בחירה לערב״. כשיש סתירה, הבחירה לערב קודמת לסוגי האוכל ולטקסט שבפרופיל.
- העדפת התזונה (צמחוני / טבעוני) נשמרת תמיד, גם כשנבחרה ״בחירה לערב״, ונבדקת לפי קיום מנות מתאימות במסעדה.
- ״לא משנה״ בפרמטר משותף מסיר אותו מהסינון. דילוג על העדפת אוכל לערב משתמש בפרופיל השמור; אפשרות זו תנוסח בנפרד כדי לא לבלבל עם ״לא משנה״.
- ״לא משנה״ בהעדפת אוכל לערב משמעו שאין העדפת סוג אוכל באותו חיפוש; אין בכך מחיקה של הפרופיל, והעדפת התזונה נשארת בתוקף.
- אין בחירה של ״חובה״ לעומת ״העדפה״ ואין הגדרת משקלים על ידי המשתמש.
- ממשק עברי ב־RTL אמיתי, לרבות סדר רכיבים, יישור וניווט, גם כאשר שפת המכשיר אינה עברית. אין להפוך תווי עברית ידנית.
- הכיוון הוויזואלי מבוסס על Inspiration Board שאושר: שמנת, פחם, בורדו, זהב עמום וירוק זית, עם אווירה חמה ואלגנטית. לוגו המלון שמופיע ברפרנס הוא מקור השראה בלבד ואינו מיתוג האפליקציה. בגרסה הראשונה אין תמונות מסעדות.

## 4. דרישות פונקציונליות

### Features & Functional Requirements

|---|---|---|
| FR-01 | שימוש ללא הרשמה | ניתן ליצור פרופילים ולהפעיל חיפוש ללא חשבון או התחברות. |
| FR-02 | פרופילי סועדים מקומיים | שם לתצוגה, סוגי אוכל, טקסט חופשי (עד 200 תווים) ותזונה זמינים אחרי סגירה ופתיחה מחדש. לא ניתן לשמור שני פרופילים באותו שם. |
| FR-03 | בחירת משתתפים | החיפוש כולל רק את הפרופילים שנבחרו ליציאה; ניתן לבחור בין 1 ל־10 משתתפים. |
| FR-04 | העדפה לערב | העדפה זמנית גוברת על סוגי האוכל והטקסט שבפרופיל בלי לשנות את הפרופיל. העדפת התזונה נשארת בתוקף. |
| FR-05 | חיפוש לפי זמן נסיעה | ניתן לבחור מיקום נוכחי או כתובת ידנית, וזמן נסיעה מרבי ברכב מתוך 15 / 30 / 45 / 60 דקות. |
| FR-06 | חיפוש לפי ערים / אזורים | ניתן לבחור אזור אחד או יותר מתוך רשימה קבועה בישראל, ללא תלות בזמן נסיעה וללא דרישת מיקום המכשיר. |
| FR-07 | תקציב משותף לאדם | רשימה סגורה: עד 100 ₪, 100–200 ₪, 200–300 ₪, 300–400 ₪, 400 ₪ ומעלה, וכן ״לא משנה״. ניתן לבחור יותר מטווח אחד; מסעדה מתאימה אם המחיר המשוער שלה נמצא באחד הטווחים שנבחרו. בקצוות משותפים אין כפילות לוגית בין טווחים. |
| FR-08 | העדפות נוספות משותפות | כשרות: ״כשר עם תעודה״, ״לפחות ללא חזיר ופירות ים״, ״לא משנה״. מסעדה כשרה עם תעודה עונה גם על האפשרות האמצעית. אווירה: בחירה של עד שתיים מתוך רומנטית / משפחתית / תוססת / שקטה / עסקית, או ״לא משנה״; שתי אווירות הן חלופות. |
| FR-09 | יצירת המלצות עם חיפוש ברשת | הבקשה עוברת דרך Backend ל־OpenAI, עם הפרמטרים הפעילים והעדפות המשתתפים ללא שמותיהם. |
| FR-10 | תוצאות מדורגות | יעד של חמש מסעדות אמיתיות, עם מיקום בדירוג, הסבר לכל משתתף ולקבוצה, כתובת, טווח מחיר משוער לאדם וקישור לאתר המסעדה; כשאין לה אתר — קישור לעמוד אחר שמתאר אותה. במסלול זמן נסיעה מוצג גם זמן נסיעה משוער. אין תמונות בגרסה הראשונה. |
| FR-11 | התאמות חלקיות | רק כשאין חמש מסעדות ללא חריגה ידועה משלימים בהתאמות חלקיות; חריגה מפרמטר אחד קודמת לחריגה משניים, וכן הלאה. מותר לחרוג גם מתקציב, אזור או זמן נסיעה, תוך פירוט החריגות. היקף ישראל נשמר. |
| FR-12 | המלצות נוספות | הבקשה מחזירה עוד עד חמש מסעדות לפי אותם פרמטרים, ללא חזרה על מסעדות שכבר הוצגו באותו חיפוש, ככל שקיימות תוצאות נוספות. התוצאות החדשות מתווספות מתחת לקודמות. |
| FR-13 | מועדפים | ניתן לשמור מסעדה במכשיר ולחזור אליה בשימוש עתידי. לחיצה על לב מלא מסירה את המסעדה מהמועדפים. |
| FR-14 | שיתוף רשימה | ניתן לשתף מסעדות, קישורים והסבר קבוצתי באמצעות אפשרויות השיתוף של המכשיר. אין לכלול שמות משתתפים, מזהים או הסברים אישיים בשיתוף. |
| FR-15 | טעינה וכישלון | בזמן העבודה מופיע מצב טעינה ברור; בכישלון מופיעה הודעת שגיאה וכפתור ״ניסיון חוזר״. |
| FR-16 | מועד היציאה | ניתן לבחור תאריך ושעה, לרבות מועד עתידי. מסעדה שידוע שהיא סגורה במועד שנבחר אינה מוצגת; מסעדה ששעות הפתיחה שלה לא ידועות מסומנת ״לא אומת״. |
| FR-17 | דירוגים וביקורות ברשת | החיפוש אוסף דירוגים וביקורות מאתרים רלוונטיים ומשתמש בהם לאחר התאמה לדרישות הקבוצה. המקורות שעליהם מסתמכים נשמרים עם התוצאה לצורך ביסוס ההסבר. |
| FR-18 | מחיקת פרופיל | ניתן למחוק פרופיל לאחר אישור. המחיקה מסירה אותו מהמכשיר ומבחירת המשתתפים. |

### כללי התאמה
1. עבור כל משתתף מורכבת תמונת העדפות מהפרופיל ומהעדפת הערב, בהתאם לכללי הקדימות.
2. פרמטרים שסומנו ״לא משנה״ אינם משפיעים על הסינון או הדירוג.
3. לכל פרמטר פעיל נקבע אחד משלושה מצבים: **מתאים**, **לא ידוע** (לא נמצא מידע מאומת) או **לא מתאים** (חריגה ידועה).
4. סדר הקדימות: מסעדות ללא חריגה ידועה קודמות; ביניהן, מסעדה שכל הפרמטרים שלה אומתו קודמת, ואחריה לפי מספר הפרמטרים הלא ידועים בסדר עולה. רק כשאין חמש מסעדות ללא חריגה ידועה משלימים בהתאמות חלקיות, לפי מספר החריגות בסדר עולה. בין מסעדות בעלות התאמה דומה, דירוגים וביקורות ברשת משמשים להעדפה. דירוג גבוה ברשת אינו עוקף את סדר ההתאמה הזה.
5. כל חריגה וכל פרמטר לא ידוע מפורטים במפורש בכרטיס. כלל זה חל גם על בקשת המלצות נוספות, לאחר הסרת מסעדות שכבר הוצגו.
6. דירוגים ממקורות שונים אינם מוצגים כאילו נמדדו באותה סקאלה; מידע חסר אינו הופך לדירוג מומצא. שיטת שקלול מספר הביקורות, עדכניותן והמקורות מוגדרת ב־Architecture תוך שמירה על קדימות דרישות הקבוצה.
7. התאריך והשעה משמשים לבדיקת שעות פתיחה לפי המידע הזמין, ואינם הבטחה לשולחן פנוי.
8. אין להמציא מסעדות, קישורים או נתוני נסיעה כדי להשלים חמש תוצאות. מידע חסר או משוער יסומן בהתאם.

### Edge Cases & Error Handling
- **אין משתתפים שנבחרו:** יש להשלים בחירה לפני שליחת הבקשה.
- **יותר מ־10 משתתפים:** לא ניתן לבחור משתתף נוסף, ומוצגת הודעה.
- **שם כפול:** לא ניתן לשמור פרופיל בשם שכבר קיים; מוצגת הודעה.
- **אין העדפה לערב:** משתמשים בהעדפות הקבועות, אם קיימות.
- **״בחירה לערב״ ריקה:** לא ניתן להמשיך עד שנבחר סוג אוכל או נכתב טקסט.
- **העדפות סותרות בקבוצה:** מוצגות האפשרויות המתאימות ביותר עם הסבר על ההתאמה והפערים לכל משתתף.
- **פחות מחמש תוצאות מבוססות:** מוצגות התוצאות הזמינות והסבר שלא נמצאו חמש; אין השלמה מלאכותית.
- **אין מסעדות חדשות:** מוסבר שלא נמצאו המלצות נוספות בפרמטרים הנוכחיים.
- **מסעדה סגורה במועד שנבחר:** אינה מוצגת בתוצאות.
- **אין הרשאת מיקום:** ניתן להזין כתובת ידנית או לבחור בחיפוש לפי ערים / אזורים.
- **אין חיבור או כשל בשירות:** הודעת שגיאה וניסיון חוזר, בלי לאבד את פרטי היציאה. חיפוש המלצות חדשות מחייב חיבור לרשת.
- **מידע ברשת חסר או לא חד־משמעי:** מוצגת אי־הוודאות במקום לייחס למסעדה נתון ודאי, לרבות כשרות, מחירים, שעות פתיחה ודירוגים.
- **אין אתר למסעדה:** מוצג קישור לעמוד אחר שמתאר אותה; אם אין גם כזה, הכרטיס מוצג ללא קישור ומסומן בהתאם.
- **מועד עתידי:** תוצאת החיפוש מבוססת על שעות הפתיחה הידועות, עם סימון אי־ודאות כשאין מידע למועד שנבחר.
- **שיתוף:** ההסברים האישיים נשארים בתצוגת המכשיר ואינם נכללים בטקסט המשותף.
- **פתיחה בדפדפן ולא מהאייקון במסך הבית:** מוצגת הנחיה קצרה איך לשמור את האפליקציה למסך הבית. ב־iPhone הנתונים שנשמרו באפליקציה המותקנת אינם זמינים בלשונית דפדפן רגילה, ולהפך.

## 5. דרישות טכניות ואילוצים

| תחום | החלטה מאושרת |
|---|---|
| Platforms | אפליקציית אינטרנט (PWA) לדפדפני הטלפון — Safari ב־iPhone ו־Chrome ב־Android — הניתנת לשמירה למסך הבית ולפתיחה כמסך מלא. בחירת הטכנולוגיה בשלב Architecture. |
| הפצה | פרטית למשפחה וחברים קרובים באמצעות קישור; ללא חנויות אפליקציות וללא עלות התקנה. |
| שפה וכיווניות | עברית, RTL תמיד, ללא תלות בשפת המכשיר. |
| היקף גאוגרפי | ישראל בלבד בגרסה הראשונה. |
| Authentication | ללא הרשמה וללא התחברות. |
| שמירה | פרופילי סועדים ומועדפים נשמרים במכשיר בלבד, באחסון של האפליקציה בדפדפן; אין סנכרון בין מכשירים. המידע אינו רגיש ואינו דורש הצפנה. אין גיבוי בגרסה הראשונה. |
| אופן שימוש קבוצתי | אדם אחד מזין עבור כל המשתתפים במכשיר שלו. |
| AI | OpenAI עם חיפוש ברשת לצורך הפקת המלצות. בחירת מודל ודרך החיפוש בשלב Architecture. |
| Backend | הגישה ל־AI דרך Backend בלבד; מפתחות API אינם נחשפים באפליקציה. |
| ביצועים | ברוב החיפושים התוצאות מוצגות תוך 30 שניות. |
| פרטיות הבקשה | שמות המשתתפים אינם נשלחים ל־AI. מזהים זמניים מקשרים את ההסברים בחזרה לשמות במכשיר. |
| העברת נתונים | לצורך החיפוש מועברות העדפות ומועברים פרטי המיקום הדרושים. שמירה מקומית אינה משמעה שכל העיבוד מתרחש במכשיר. |
| מיקום וזמן נסיעה | תמיכה במיקום נוכחי או כתובת ידנית במסלול זמן נסיעה. מקור ואופן חישוב זמן הנסיעה נקבעים ב־Architecture. |
| תלות ברשת | חיפוש ברשת ויצירת המלצות מחייבים חיבור. |
| תהליך עבודה | Gated: אישור כל Milestone לפני המעבר לבא. |

מדיניות שמירה של בקשות אצל שירותי העיבוד, מנגנוני הגנה על ה־Backend ומקורות נתוני נסיעה מפורטים ב־Architecture. אין התחייבות למדיניות של ספק חיצוני או לנתוני זמן אמת.

## 6. Out of Scope

- איסוף אלרגיות ורגישויות, שמירתן, סינון לפיהן או העברתן ל־AI. לא יופיעו שדות או הסברים בנושא בממשק.
- הרשמה, התחברות, חשבונות ותפקידים שונים.
- שמירת פרופילים או מועדפים בשרת וסנכרונם בין מכשירים.
- מילוי ההעדפות על ידי משתתפים ממכשירים נפרדים.
- המלצות מחוץ לישראל.
- סינון לפי חניה, נגישות או התאמה לילדים.
- שדות נפרדים נוספים כגון רמת רעש וישיבה בפנים / בחוץ; אווירה נשארת פרמטר משותף אחד.
- תמונות מסעדות בגרסה הראשונה.
- אפליקציות native, פרסום בחנויות האפליקציות ומסמך מדיניות פרטיות לחנויות.
- הזמנת שולחן, תשלום, משלוחים או הבטחת זמינות שולחנות בזמן אמת.
- בחירת דרישות ״חובה״ / ״העדפה״ או משקלים ידניים.
- שמירת היסטוריית חיפושים.
